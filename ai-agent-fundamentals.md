## 2. What Is an LLM?

**LLM** stands for **Large Language Model**. It is the core engine that processes input and produces output.

Input and output capabilities vary between models:

- Many LLMs accept text input and produce text output.
- Multimodal models may accept text, images, audio, or video while still producing text output.
- If a tool returns an image, the chosen LLM must support image input. Otherwise, the system may return an error such as: `This LLM is not capable of handling images.`
- Content sent to and generated by an LLM is measured in tokens, according to the provider's token-accounting method.
- Excessive or irrelevant context can make it more difficult for a model to identify the important information and may reduce response quality.

## 3. What Is an Agent?

The transcript implies the following definition:

> An agent combines an LLM, tools, and properly defined functions to perform work toward a specific outcome.

Key points about an agentic setup include:

- The LLM calls tools or functions to complete tasks.
- APIs can be exposed to the LLM as callable tools.
- An agent should receive the appropriate set of tools—neither too many nor too few.
- An agent's effectiveness depends on:
  - **Prompt engineering:** how the request and instructions are written.
  - **Tool engineering:** which tools are provided and how they are defined.
  - **Modality matching:** whether the LLM can process each tool's output.

## 4. Tools and Tool Engineering

### What Are Tools?

Tools are functions or APIs that an LLM can call to perform specific tasks.

Examples include:

- A SQL query tool that returns a table.
- A browser screenshot tool that returns an image.
- A calculation tool that returns a number.
- Tools that return images, videos, or audio.
- Architecture-diagram tools.
- Software APIs converted into function tools and connected to an LLM.

### Tool Engineering

> Besides prompt engineering, tool engineering is also a skill. You need to provide the correct set of tools—not too many and not too few—to get your job done.

Tool outputs can have different modalities, such as tables, numbers, images, videos, and audio. The LLM must support the modality returned by a tool.

For example, a browser screenshot tool returns an image. Depending on the API, that image may be encoded or referenced before being sent to a vision-capable model. Images can consume substantial context and increase cost, especially at high resolutions. The transcript's speaker therefore disabled the screenshot tool temporarily to reduce token consumption.

## 5. Modality

> When we talk about tools, modality is important.

| Tool output | Example | LLM requirement |
|---|---|---|
| Table | SQL query | Must process structured text or data |
| Number | Calculation tool | Must process text or structured data |
| Image | Browser screenshot | Must support image input |
| Video | Video-analysis tool | Must support video input or extracted frames/transcripts |
| Audio | Voice tool | Must support audio input or receive a transcript |

Many LLMs work with text input and output. Multimodal models can also process one or more additional input types, such as images, audio, or video.

## 6. Tokens and Tokenization

### What Is a Token?

> Any input that goes into the LLM can be broken down into tokens.

Tokens are units into which a model divides input and output. A token may represent a whole word, part of a word, punctuation, or another text fragment. Tokenization differs between models.

For example:

- A name such as `Mohammed` may be divided into one or more tokens.
- A sentence is divided into a sequence of tokens rather than always using one token per word.

### Token Cost

Providers may charge different rates for input and output tokens. Output tokens are often more expensive than input tokens, although the exact prices depend on the provider and model.

```text
Total cost = (input tokens × input rate) + (output tokens × output rate)
```

### Tokens and Response Quality

When the supplied context becomes very large, irrelevant details may distract the model from the task. Good context management helps the model focus on the most useful information and can reduce cost.

### Images and Tokens

Images may be transferred as encoded data or file references, depending on the API. Providers calculate image-input usage differently, commonly considering factors such as image dimensions and detail level. Larger or higher-detail images generally consume more input budget and cost more.

## 7. Hosting and Cost Models

| Model or deployment type | Billing approach | Description |
|---|---|---|
| Hosted API | Usage-based | Charges commonly depend on model usage, including input and output tokens. |
| Subscription service | Prepaid or recurring | Provides access subject to the service's plan limits and terms. |
| Self-hosted LLM | Infrastructure-based | Requires owned or rented compute, electricity, operations, and scaling. |

GPUs become important when deploying an LLM on your own infrastructure. Self-hosting avoids third-party inference charges, but it still carries hardware, electricity, maintenance, and scalability costs.

## 8. MCP (Model Context Protocol)

In an organization, multiple projects may need the same tools—for example, a SQL query tool. If each project creates its own implementation, this can result in duplication and inconsistency.

**Model Context Protocol (MCP)** standardizes how AI applications connect to tools and contextual data. It allows commonly used capabilities to be developed once and reused across multiple projects or agents.

## 10. Core Message

- Choose the LLM and tools based on the desired outcome.
- Match the LLM's modality capabilities to the outputs produced by its tools.
- Engineer the toolset carefully—neither too many tools nor too few.
- Understand token and cost implications, especially when working with images.
- Use MCP to make shared tools reusable across projects and agents.
